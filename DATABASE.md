# 钩玄数据库设计

本文记录当前账号认证表设计，并保留 v1 后续业务的数据关系参考。产品与架构范围见 [PLAN.md](PLAN.md)，数据库基础和账号认证分别归入 `build-service-foundation` 与 `add-account-access` change。

当前只创建 `users`、`auth_sessions`、`refresh_tokens` 三张登录业务表。其余表在对应功能实际开发时复核设计并新增迁移，不预建 ORM 模型、业务表或空队列。Alembic 自身的迁移版本表不属于业务表。

## 当前登录表

| 表               | 职责                                           |
| ---------------- | ---------------------------------------------- |
| `users`          | 账号、密码哈希、角色与启用状态                 |
| `auth_sessions`  | 当前访问凭据哈希、滑动期限、绝对期限与吊销状态 |
| `refresh_tokens` | 刷新凭据哈希与消费记录，用于轮换和重放检测     |

### 合并后的处理约束

| 关系     | 约束                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| 生效回答 | `effective_answer_id` 只能指向本问题的候选；新候选成功后原子切换，失败或取消保留原回答                                  |
| 问答队列 | `qa_runs` 自身承载领取和执行状态；每个会话最多一个活动运行，迟到写入必须检查状态、租约代次与期限                        |
| 资料队列 | `ingestion_tasks` 顺序推进阶段；重试增加执行代次，等待审核不占 worker，旧执行不能覆盖新状态                             |
| 发布评测 | v1 使用脚本输出报告并人工复核；报告保存在私有存储，发布记录绑定报告摘要和配置；历史报告保留，已发布记录不被后续评测覆盖 |

## 账号认证表

### users — 账号表

| 字段            | 类型           | 必填 | 默认值／约束                        |
| --------------- | -------------- | ---- | ----------------------------------- |
| `id`            | `UUID`         | 是   | 主键，服务端生成                    |
| `email`         | `VARCHAR(320)` | 是   | 去除首尾空白、转小写，唯一          |
| `password_hash` | `VARCHAR(255)` | 是   | Argon2id 哈希                       |
| `role`          | `VARCHAR(16)`  | 是   | 默认 `user`，只允许 `user`、`admin` |
| `is_active`     | `BOOLEAN`      | 是   | 默认 `true`                         |
| `created_at`    | `TIMESTAMPTZ`  | 是   | 创建时间                            |
| `updated_at`    | `TIMESTAMPTZ`  | 是   | 最近修改时间                        |

管理员初始化通过 CLI 执行。已有管理员时保持原账号和密码；普通账号使用同一张表。

账号创建与密码重置接受 12 到 1024 个字符的密码；原始密码和令牌不保存到业务表或日志。所有时间字段使用带时区的时间戳。

### auth_sessions — 登录会话表

| 字段                  | 类型           | 必填 | 默认值／约束                                 |
| --------------------- | -------------- | ---- | -------------------------------------------- |
| `id`                  | `UUID`         | 是   | 主键，服务端生成                             |
| `user_id`             | `UUID`         | 是   | 外键 → `users.id`                            |
| `device_name`         | `VARCHAR(120)` | 是   | 展示名称，允许重复                           |
| `access_token_hash`   | `BYTEA`        | 是   | SHA-256 哈希，32 字节，唯一                  |
| `access_expires_at`   | `TIMESTAMPTZ`  | 是   | 访问凭据到期时间                             |
| `idle_expires_at`     | `TIMESTAMPTZ`  | 是   | 空闲到期时间，成功续期后延长                 |
| `absolute_expires_at` | `TIMESTAMPTZ`  | 是   | 从首次登录计算，续期不延长                   |
| `revoked_at`          | `TIMESTAMPTZ`  | 否   | 空值表示未吊销                               |
| `revoked_reason`      | `VARCHAR(32)`  | 否   | 退出、密码重置、账号停用、设备吊销或令牌重放 |
| `created_at`          | `TIMESTAMPTZ`  | 是   | 首次登录时间                                 |
| `last_refreshed_at`   | `TIMESTAMPTZ`  | 是   | 创建时取登录时间，成功续期后更新             |

### refresh_tokens — 刷新凭据历史表

| 字段          | 类型          | 必填 | 默认值／约束                |
| ------------- | ------------- | ---- | --------------------------- |
| `token_hash`  | `BYTEA`       | 是   | 主键，SHA-256 哈希，32 字节 |
| `session_id`  | `UUID`        | 是   | 外键 → `auth_sessions.id`   |
| `issued_at`   | `TIMESTAMPTZ` | 是   | 签发时间                    |
| `consumed_at` | `TIMESTAMPTZ` | 否   | 空值表示尚未用于续期        |

当前刷新凭据的期限由登录会话决定，因此这里不重复保存到期时间。已消费记录用于识别重放，在对应会话仍可续期期间保留。

## 认证索引与约束

| 表                                 | 索引／约束                                                                               | 用途                           |
| ---------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------ |
| `users`                            | `UNIQUE(email)`                                                                          | 邮箱唯一及登录查询             |
| `users`                            | `CHECK(email = lower(btrim(email)))`                                                     | 防止写入未规范化邮箱           |
| `users`                            | `CHECK(role IN ('user', 'admin'))`                                                       | 限定角色                       |
| `auth_sessions`                    | `UNIQUE(access_token_hash)`                                                              | 按访问凭据查找会话             |
| `auth_sessions`                    | `(user_id, created_at)`                                                                  | 查询用户登录会话               |
| `auth_sessions`                    | `(idle_expires_at)`                                                                      | 查找到期会话                   |
| `auth_sessions`                    | `CHECK(access_expires_at <= idle_expires_at AND idle_expires_at <= absolute_expires_at)` | 凭据期限不越过会话期限         |
| `auth_sessions` / `refresh_tokens` | `CHECK(octet_length(令牌哈希字段) = 32)`                                                 | 固定 SHA-256 哈希长度          |
| `refresh_tokens`                   | 主键 `token_hash`                                                                        | 查询当前或历史刷新凭据         |
| `refresh_tokens`                   | `(session_id)`                                                                           | 按会话查询和清理刷新历史       |
| `refresh_tokens`                   | `UNIQUE(session_id) WHERE consumed_at IS NULL`                                           | 每个会话最多一条未消费刷新凭据 |

## 长期登录期限与事务

| 项目               | 规则                                                     |
| ------------------ | -------------------------------------------------------- |
| 访问凭据           | 每次签发有效 15 分钟，不超过会话到期时间                 |
| 空闲期限           | 首次登录及成功续期后设置为 30 天，不超过绝对期限         |
| 绝对期限           | 首次登录起 180 天，保持不变                              |
| 刷新轮换           | 消费旧刷新凭据、创建新凭据、替换访问凭据，在同一事务提交 |
| 刷新重放           | 撤销对应登录会话，撤销提交后再返回失效错误               |
| 密码重置／账号停用 | 修改账号并撤销全部登录会话，在同一事务提交               |

## 迁移顺序

| 阶段           | 数据库操作                                                              |
| -------------- | ----------------------------------------------------------------------- |
| 当前登录功能   | 准备 Postgres 与 Alembic，只创建三张认证业务表，再通过 CLI 初始化管理员 |
| 知识库开发     | 按实际摄取和检索需求安装 pgvector 扩展，迁移资料、任务、索引和分块表    |
| 问答与发布开发 | 按已确认接口及事务需求迁移会话、运行、事件、发布及辅助表                |

各阶段只迁移当时已有实际消费者的结构。每次实施同步更新本文与对应 change，正式表结构以经验证的 Alembic 迁移为准。
