# v1 change 实施计划

本计划以 [PLAN.md](../PLAN.md) 的已确认方案为准，按可以独立验证的闭环拆分。这里只安排 v1；付费、自助注册、OCR、多端增量同步、执行断点恢复和高可用仍属于 v2。

现有代码已具备 workspace、Electron 安全骨架与 Astryx 样式管线、FastAPI 健康接口、API 镜像及基础 Compose。数据库、账号、知识库、问答业务、客户端业务与官网尚未实现。以下 7 个 change 已创建，均包含 proposal、design、spec 和 tasks，处于待实施状态。

## 拆分与依赖

| 顺序 | Change                                                                   | 实现闭环                                                                          | 依赖         | 验收出口                                                               |
| ---- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------- | ------------ | ---------------------------------------------------------------------- |
| 1    | [build-service-foundation](changes/build-service-foundation/proposal.md) | Postgres / pgvector、ORM、迁移、私有对象存储与开发基础设施                        | 已有工程骨架 | 空库迁移、数据库与存储连接可验证，缺少迁移时服务拒绝启动               |

| 3    | [build-knowledge-base](changes/build-knowledge-base/proposal.md)         | 管理员上传、受限解析、审核、分块与索引、资料 worker、候选整库 manifest 与摄取用量 | 1、2         | 文本 PDF / Markdown 可形成已审核、可查询的冻结候选；失败阶段可安全重试 |
| 4    | [build-rag-service](changes/build-rag-service/proposal.md)               | 混合检索、有界工作流、自动摘要、持久运行与事件、会话和引用、候选评测、发布及回滚  | 1、2、3      | 首批候选经评测发布后，可通过 API 完成流式问答、核验、取消、重跑与恢复  |
| 5    | [build-qa-client](changes/build-qa-client/proposal.md)                   | Main 请求认证与 SSE、类型化 Preload、Hash 路由、问答和管理员页面、SQLite 缓存     | 2、3、4      | 桌面端完成登录、问答、来源核对、断线恢复、离线历史与知识库管理         |

| 7    | [prepare-v1-release](changes/prepare-v1-release/proposal.md)             | 分栈 CI、真实模型与私有资料验收、生产部署、备份恢复、图标、签名公证及安装验证     | 1–6          | 契约与质量检查通过，完整部署可恢复，安装包可安装启动，官网提供有效下载 |

这 7 个 change 是本次明确要求的 v1 批量拆分计划，一并保留供评审，实际按依赖顺序实施并验收、归档；官网可以与服务开发并行。每个 change 只在有真实调用方时加入依赖、目录与接口，不预建空的业务层或计费框架。

知识库 change 负责候选内容与索引，不提前开放发布接口。RAG change 复用候选执行内部评测，再实现发布门禁与整库指针切换。内部评测可以使用未发布候选，普通问答始终使用提交时绑定的已发布版本，首次入库不存在启动依赖循环。

## v1 验收归属

| 范围                                 | 主要负责的 change    | 必须保留的约束                                                                                         |
| ------------------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------ |
| 数据库、迁移、私有存储与基础健康检查 | 服务基础             | 使用同一 ORM 连接池；启动检查迁移，不在业务请求中建表；空语料不阻断账号与管理入口                      |
| 账号生命周期与权限                   | 账号权限             | 两个角色、管理员受控创建、令牌哈希与轮换、重放检测、设备吊销、服务端归属校验                           |
| 上传、解析、审核与失败重试           | 知识库摄取           | PDF / Markdown 格式与资源上限、上传及重试幂等、独立资料队列、租约失效阻断迟到写入                      |
| 不可变资料、分块与索引               | 知识库摄取           | 完整候选 manifest；产品、版本与权限元数据；embedding、维度与词法配置一致                               |
| 候选评测、发布与回滚                 | RAG 服务             | 评测绑定候选与配置；原子切换整库指针；并发发布冲突不覆盖；已提交运行继续使用原版本                     |
| 检索与回答质量                       | RAG 服务             | 混合召回、排序与条款上下文；最多两轮检索和一次修订；无证据、缺少事实或来源冲突时说明或追问             |
| 长会话自动摘要                       | RAG 服务             | 按输入预算触发、每次运行最多一次；用户事实回查原消息；摘要失败降级；摘要不作为保险证据                 |
| 会话、提交与最新一轮重跑             | RAG 服务             | 原子创建与账号幂等键；同会话一个活动运行；重跑复用用户消息，失败或取消保留原生效回答                   |
| 执行、取消与事件恢复                 | RAG 服务             | 独立问答 worker；短事务领取与租约校验；终态一次；断线不取消，执行中断失败后由用户重跑                  |
| 结构化流式输出                       | RAG 服务、桌面客户端 | 部分 JSON 仅用于正文预览；完整原始 JSON 严格校验后保存；权威消息快照先于完成事件；预览与终态有明确区分 |
| 来源与会话删除                       | RAG 服务、桌面客户端 | 自包含引用快照；归属检查；删除撤销运行并阻断迟到内容；缓存 ID 批量核对不以分页缺席判断删除             |
| 模型调用用量                         | 知识库摄取、RAG 服务 | 摄取、摘要、问答与评测关联实际调用 ID；成功、失败、取消均记录；未知用量待核对；v1 无钱包与支付实现     |
| Main 统一请求认证                    | 桌面客户端           | HTTP、上传及 SSE 共用认证边界；并发续期合并；最多一次认证重放；保留幂等键；网络异常保留登录状态        |
| 路由、聊天界面与管理页面             | 桌面客户端           | Hash 文件路由、左右布局、管理员菜单及路由守卫；切换页面不取消服务端运行                                |
| 主题与外观                           | 桌面客户端           | 浅色、深色、跟随系统，默认跟随系统；偏好按账号保存，离线可修改；原生与网页配色一致，启动避免主题闪烁   |
| 缓存、账号隔离与离线历史             | 桌面客户端           | SQLite 投影和连续已应用序号同事务；终态立即提交；按账号与登录代次隔离；离线只读，草稿独立保存          |
| IPC、导航与资源安全                  | 桌面客户端           | 类型化白名单和运行时校验；凭据只在 Main；来源文本和 Markdown 资源受访问与导航规则约束                  |
| 官网与桌面产物隔离                   | 官网、发布验证       | 静态官网独立构建；客户端下载包不含官网文件；真实下载地址在对外发布前核对                               |
| 完整启动、契约 CI 与真实质量验收     | 发布验证             | 两类 worker 独立进程；先迁移再启动；首次管理员 CLI；锁文件与生成契约门禁；私有 golden 回归及人工复核   |
| 发布标识、签名、公证与安装           | 发布验证             | 钩玄图标与显示名、固定 appId 和用户目录、ASCII 产物名、手动更新、旧客户端契约兼容性                    |
