## Context

依赖服务基础完成后实施。当前没有账号表与公开业务路由；资源归属由后续业务查询使用同一身份边界。v1 只允许运维通过受控 CLI 管理账号。

## Goals / Non-Goals

**Goals:** 登录、续期和吊销具有稳定状态及错误契约，角色和归属校验可被实际路由复用。

**Non-Goals:** 不做自助注册、邮件找回、外部身份平台、多级角色或付费权限。

## Decisions

### 密码与受控初始化

邮箱规范化后唯一，密码以 Argon2id 哈希保存，角色只允许 user / admin。CLI 从安全交互或部署密钥输入读取密码，不把密码写进命令参数或日志；首次管理员初始化可重复执行，但不覆盖已有账号或密码。后续创建、停用、密码重置和设备吊销均由受控 CLI 执行。

### 登录会话

数据库保存设备会话、访问令牌与刷新令牌哈希及期限，不保存原始令牌。访问令牌初值 15 分钟，刷新令牌 30 天。刷新在锁定会话的事务中轮换，保留识别旧令牌重放所需的关系；重放使该设备会话失效。退出、账号停用、密码重置和设备吊销撤销相应会话。

使用不透明令牌而非再引入 JWT 签名与吊销缓存，使现有数据库即可完成明确撤销。并发刷新行为需要服务端测试，客户端 single-flight 在客户端 change 实现。

### HTTP 与授权

`/v1/auth` 提供登录、刷新、退出与当前账号接口，Pydantic 请求响应就近定义在路由。稳定错误码区分访问过期、刷新失效、会话吊销和权限不足；公开登录失败不透露邮箱是否存在。

`auth.py` 仅提供实际路由需要的身份和角色校验；会话、运行、来源与知识库各自在查询中限定归属或管理权限。不能只依赖 Renderer 路由守卫。

## Risks / Trade-offs

- 令牌哈希查询增加数据库访问 → 使用唯一索引与连接池，先验证目标负载，不加未需要的缓存服务。
- 续期响应丢失导致新令牌未收到 → 保持轮换与重放规则，返回明确登录恢复状态，不宽泛放开旧令牌。
- 初始化误覆盖管理员 → 唯一约束及幂等初始化测试，不以重复初始化重置凭据。

## Migration Plan

迁移用户和设备会话表，先在空库运行管理员 CLI，再验证两个角色的 HTTP 生命周期。迁移和接口与旧健康接口共存；后续回退不得让被吊销凭据重新有效。
