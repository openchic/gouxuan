## Context

Postgres 连接与 Alembic 迁移已接入，开发数据库已按 [DATABASE.md](../../../DATABASE.md) 创建三张认证业务表。登录及账号管理使用同一身份边界，资源归属由后续业务查询实现。v1 只允许运维通过受控 CLI 管理账号。

## Goals / Non-Goals

**Goals:** 登录、续期和吊销具有稳定状态及错误契约，角色和归属校验可被实际路由复用。

**Non-Goals:** 不做自助注册、邮件找回、外部身份平台、多级角色或付费权限。

本次只创建 `users`、`auth_sessions`、`refresh_tokens` 三张认证业务表。对象存储、pgvector、知识库、问答、计量及发布表均在对应功能实际开发时接入，不预建占位结构。

## Decisions

### 密码与受控初始化

邮箱规范化后唯一，密码以 Argon2id 哈希保存，角色只允许 user / admin。CLI 从安全交互或部署密钥输入读取密码，不把密码写进命令参数或日志；首次管理员初始化可重复执行，但不覆盖已有账号或密码。后续创建、停用、密码重置和设备吊销均由受控 CLI 执行。

### 登录会话

`users` 保存规范化邮箱、Argon2id 密码哈希、角色与启用状态。`auth_sessions` 保存当前访问令牌哈希、访问期限、空闲期限、绝对期限及吊销状态；设备名称只作展示，允许重复。`refresh_tokens` 保存刷新令牌哈希和消费时间，按会话保留识别旧令牌重放所需的历史。令牌哈希使用 32 字节 SHA-256，原始令牌只返回客户端。

访问令牌初值 15 分钟；会话空闲期限在首次登录和成功续期后设置为 30 天，绝对期限为首次登录起 180 天。续期只延长空闲期限，访问期限与空闲期限都不能越过绝对期限。过期会话不能通过续期恢复。

刷新事务按用户、会话顺序加锁，先消费旧刷新记录，再创建新记录并替换访问令牌。部分唯一索引保证每个会话最多一条未消费刷新记录。检测到重放时提交会话撤销，再返回错误，避免异常回滚撤销操作。退出、账号停用、密码重置和设备吊销撤销相应会话；密码计算放在短事务外，写入前重新检查账号及密码版本。

已消费刷新记录在对应会话仍可续期期间保留；到期或撤销后的清理由当前认证表承担，不额外创建清理任务表。服务端响应公布当前凭据期限，客户端收到新凭据后安全替换本地保存的刷新凭据。

使用不透明令牌而非再引入 JWT 签名与吊销缓存，使现有数据库即可完成明确撤销。并发刷新行为需要服务端测试，客户端 single-flight 在客户端 change 实现。

### HTTP 与授权

`/v1/auth` 提供登录、刷新、退出与当前账号接口，Pydantic 请求响应就近定义在路由。稳定错误码区分访问过期、刷新失效、会话吊销和权限不足；公开登录失败不透露邮箱是否存在。

`auth.py` 仅提供实际路由需要的身份和角色校验；会话、运行、来源与知识库各自在查询中限定归属或管理权限。不能只依赖 Renderer 路由守卫。

## Risks / Trade-offs

- 令牌哈希查询增加数据库访问 → 使用唯一索引与连接池，先验证目标负载，不加未需要的缓存服务。
- 续期响应丢失导致新令牌未收到 → 保持轮换与重放规则，返回明确登录恢复状态，不宽泛放开旧令牌。
- 初始化误覆盖管理员 → 唯一约束及幂等初始化测试，不以重复初始化重置凭据。

## Migration Plan

先在空库迁移三张认证业务表，再运行管理员 CLI 并验证两个角色的 HTTP 生命周期、滑动续期、绝对期限、并发重放和吊销。重复升级不产生新业务表；后续业务通过独立增量迁移创建当时实际需要的表。迁移和接口与健康接口共存；回退不得让被吊销凭据重新有效。
