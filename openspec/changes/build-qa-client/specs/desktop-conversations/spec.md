## Purpose

为用户提供左右布局的会话问答、连续但明确未确认的正文预览及可信来源展示，使页面导航不影响后台运行，并通过按账号隔离的持久缓存支持离线阅读、断线恢复、草稿保留和服务端删除同步。

## ADDED Requirements

### Requirement: 界面先行预览

在服务端尚未接入的界面阶段，客户端 MUST 明确标记示例会话与虚构引用，保留本次窗口会话内的独立草稿，不将展示数据标为真实业务结果。

欢迎页 MUST 以紧凑问题列表提供草稿建议，避免装饰性分类卡片和重复预览提示；选择建议只填写当前草稿，不自动提交。

问答页面拆分内部渲染组件后 MUST 保持草稿、发送提示、引用展开和路由行为不变，页面入口只负责状态与布局组合。知识库页面的筛选、表格和详情也 MUST 作为页面私有组件维护，各自持有样式，页面入口只负责状态与组合。

#### Scenario: 使用推荐问题

- **WHEN** 用户选择欢迎页的推荐问题
- **THEN** 问题填入输入区并获得焦点，服务未接入时发送仍提示不可用且保留草稿

#### Scenario: 预览中提交

- **WHEN** 用户在未接入服务的工作台发送问题
- **THEN** 提示服务尚未接入，保留草稿且不创建虚假会话或回答

#### Scenario: 预览中导航

- **WHEN** 用户切换示例会话、设置或返回新建会话
- **THEN** 路由和前后导航有效，对应草稿保留，引用弹层明确说明示例来源

### Requirement: 路由与左右问答布局

客户端 MUST 以页面路由管理登录、会话和设置，左侧从新建会话与搜索开始并展示最近会话，右侧显示消息及输入；问答侧栏不展示品牌区或为其保留空白占位，右侧不展示新建会话或当前会话标题栏、对应分隔线和占位。选中会话由路由 ID 确定，通过侧栏选中项及问答区域的可访问名称标识；刷新与前后导航有效，URL 不包含凭据或正文。

#### Scenario: 展示对话区

- **WHEN** 用户进入新建会话或已有会话
- **THEN** 右侧直接显示欢迎内容或消息和输入区，不显示顶部会话标题栏，也不为其保留高度

#### Scenario: 使用官网输入区结构

- **WHEN** 用户进入问答页并准备输入问题
- **THEN** 输入区停靠在消息滚动区底部，使用带毛玻璃过渡的浮层和圆角 ChatComposer；输入默认单行起始、可随内容增长但不可被用户拉伸，仅显示必要的未接入状态提示，不在输入框内重复显示知识库依据提示
- **AND** 未接入发送错误显示在输入框上方的浮层中，提供关闭按钮，不改变 dock 高度或消息区布局；关闭提示不清除当前草稿
- **AND** 输入区不显示 Enter / Shift + Enter 快捷键说明，Enter 提交和 Shift + Enter 换行仍然可用

#### Scenario: 使用官网消息列表结构

- **WHEN** 用户打开已有示例会话
- **THEN** `ChatMessageList` 直接位于 `ChatLayout` 内容区，继承 spacious 间距并按默认 bottom anchor 排列；用户消息靠右使用填充气泡，助手消息靠左使用 ghost 内容列，引用卡片继续在助手内容中可访问

#### Scenario: 新建会话

- **WHEN** 用户从草稿提交第一条问题
- **THEN** 服务端确认后才切换为返回会话路由并清理已提交草稿

#### Scenario: 切换页面

- **WHEN** 用户在运行中切换会话或设置
- **THEN** 仅切换界面订阅，服务端运行和原生事件接收继续

### Requirement: 预览、权威结果与最新重跑

客户端 MUST 区分生成、核验、完成、失败与取消，只有权威最终结果确认回答；文本结束不等于完成。最新重跑保留原回答，成功切换生效候选，失败保留原结果。

#### Scenario: 文本流结束

- **WHEN** 收到文本结束但尚未收到核验后的权威结果
- **THEN** 显示核验或未完成，不将预览标成功

#### Scenario: 重跑失败

- **WHEN** 最新一轮新候选失败或取消
- **THEN** 原生效回答仍显示，新候选保持未完成且不重复进入历史

### Requirement: 持久事件位置与恢复

缓存 MUST 原子保存消息、引用、运行状态及连续已应用事件位置，终态立即保存；重启或重连仅从已落库位置恢复，重复事件不重复消息，事件过期读取权威状态与历史。

#### Scenario: 收事件后进程退出

- **WHEN** 事件已收到但未完成缓存事务
- **THEN** 恢复使用旧已提交序号，重放不会遗漏事件或重复消息

#### Scenario: 保留期外恢复

- **WHEN** 事件无法继续重放
- **THEN** 查询权威状态和消息恢复，不能再次提交问题

### Requirement: 缓存优先与离线读

客户端 MUST 先展示当前账号缓存再按修订刷新，离线仅阅读已缓存历史及保存本地草稿和偏好，不建立离线业务写队列；缓存有期限、容量和可重建结构。

#### Scenario: 离线启动

- **WHEN** 网络不可用且当前账号有缓存
- **THEN** 可阅读历史和编辑草稿，问答、重跑及删除提示需要联网

#### Scenario: 缓存损坏

- **WHEN** 历史缓存不能读取
- **THEN** 可清理并重建历史，不破坏独立保存的界面偏好

### Requirement: 缓存 ID 核对与删除隔离

客户端 MUST 在启动、恢复网络及窗口焦点时分批核对缓存 ID，不以最近列表分页缺席认定删除；仅明确不可访问时清理对应内容，并拒绝迟到响应及事件重建。

#### Scenario: 核对失败或分页缺席

- **WHEN** 会话未在列表当前页或核对网络失败
- **THEN** 保留缓存并标待刷新，不删除有效历史

#### Scenario: 明确删除

- **WHEN** 服务端核对确认会话已删除或不可访问
- **THEN** 清理对应消息、引用和草稿，停止订阅并阻止旧事件恢复内容

### Requirement: 来源、停止与受限状态

客户端 MUST 提供可核对文本及定位版本的来源展示，停止明确调用服务端取消，并呈现登录失效、服务不可达、资料未就绪和运行限制。

#### Scenario: 来源核对

- **WHEN** 用户打开已完成回答的引用
- **THEN** 显示授权文本、出处、定位与版本

#### Scenario: 断线与停止

- **WHEN** 客户端事件断线或用户点击停止
- **THEN** 断线按状态恢复，停止发取消请求，两者界面含义明确区分
