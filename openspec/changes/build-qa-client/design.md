## Context

客户端从空 Preload、根 Astryx Theme 和安全窗口默认值开始。按用户要求先实现界面预览，完整认证、业务缓存与流式接入等待服务端契约；目录遵循 PLAN 的 Main / Preload / shared / Renderer，页面私有 hooks、components 和 api.ts 留在所属页面。

## Goals / Non-Goals

**Goals:** 一个 Main 认证与请求入口，明确账号隔离和流式终态，缓存恢复与主题偏好可验证。

**Non-Goals:** Renderer 不直接访问服务、SQL、令牌或文件；不建离线业务写队列、自定义模型配置、支付页面或另一个主题状态源。

## Decisions

### 界面预览阶段

先实现登录、问答、设置和知识库的 Hash 文件路由。示例会话、引用和资料在对应内容中明确标记为虚构展示数据，不代表真实保险条款或已登录的管理员账号。输入与筛选可用，草稿在本次窗口会话内按路由保留；未接入服务时不提交问题、不清草稿、不保存密码、不伪造登录、上传、审核或发布结果。

只引入已被页面使用的 Router 依赖。Main 先提供主题偏好和原生资料选择的专用桥接，校验调用来源与参数；资料选择只返回名称、格式和大小，不把本地路径或内容交给 Renderer。独立 SQLite 偏好库保存客户端主题，登录页、工作台和原生窗口统一使用该主题。账号隔离、历史缓存、上传及系统认证仍由后续任务实现。

路由文件只定义路径与导入页面组件，配合 Router 自动拆分。页面目录与主组件同名，界面组件使用 `index.tsx` 和同目录的 `index.css`，样式由所属组件直接引入；布局、上传弹层和错误页分别持有样式。页面私有组件留在页面的 `components/`，共享组件和 hooks 使用统一导出入口。纯状态 Provider 和无独立 DOM 的路由适配组件不创建空 CSS。根样式仅保留 Astryx 主题引入、reset、基础元素和减少动画规则；共享侧栏、错误提示及资料元数据的样式由相应共享组件持有，页面不能依赖其他页面加载 CSS。复用 Astryx 控件与语义颜色，通过现有圆角 token 将桌面控件统一为 6–8px。

问答与设置各自使用两栏布局。问答侧栏顶部直接显示新建会话与搜索，不设置品牌区，也不保留移除品牌后的空白占位。进入设置后，会话侧栏替换为通用设置、知识库菜单，右侧通过嵌套路由显示具体页面；左侧提供返回问答入口，根状态继续保留各会话草稿。设置页面按外观、账号、关于分组，关于区域只显示产品名称与版本，主题控件直接切换实际页面，不另画装饰性界面预览。欢迎页使用紧凑问题列表，知识库状态使用带数量的筛选按钮，搜索、表格和详情保持原功能。虚构回答和资料在相应内容及弹层明确标记。来源弹层保留资料标题、定位、版本和原文，标题标明虚构示例，不重复展示整行警告徽章；来源样式由问答页面持有，不依赖知识库路由加载。

登录页沿中轴排列品牌标记、登录标题、简短说明与邮箱密码表单，内容列最大宽度为 360px。页面复用 Astryx 居中登录模板的单列顺序，移除卡片容器、投影、独立宣言区和背景字标，通过留白、字重及主题令牌建立层次。输入框与提交按钮统一控件尺寸，密码切换使用带可访问名称的眼睛图标；字段保留可见标签，不重复展示英文必填标记。提交按钮下方为账号说明与认证错误共用的反馈位置并预留高度；“先看看工作台”入口独立置于下方，通过 `import.meta.env.DEV` 条件渲染，仅在开发模式保留，生产构建不生成入口 DOM、箭头或布局占位。开发认证错误仍可引导预览，生产认证错误只说明服务未接入、暂时无法登录，不指向隐藏入口。使用编译期条件，不引入新 IPC、偏好或 CSS 隐藏逻辑；本次不扩展认证或路由守卫实现。页面使用正常布局和滚动，窄屏收缩内容列，低高度窗口允许滚动访问全部操作，主题继续由根 Theme 统一控制。

登录页按用户选择试用尖端回钩，保留细尖起笔、变化的笔画厚度和向内收尖的回钩，左侧保持开口。页面私有 `LoginLogo` 通过 Vite 的 `?url` 直接引用 `build/icons/gouxuan-v1/source/app-icon.svg`，使用装饰性图片展示正式母版的完整正方形画布。图形的 `#1b1b1b`、白色背景、内边距、比例及左移 30px 的光学校正均由 SVG 自身提供，不复制路径、不另算位移，不用 CSS 再次平移。图标宽高继续使用 `--spacing-12` 与 `--spacing-3` 之和，圆角使用 `--radius-element`；页面原有背景、根主题、居中布局与间距保持不变。图片使用空 alt、`aria-hidden` 和禁用拖动，不增加焦点。移除原有的内联 `HookMark`、独立画布、局部 `color-scheme` 和重复底色；共享 `Brand`、助手头像、打包配置及菜单栏资源不在本次范围内。

用户明确反馈“不明显”是白色图标底板与浅色登录页背景过于接近，边界缺乏对比，而非图形位置问题。继续直接消费最新 SVG 母版，不调整图形、颜色或定位；仅在 `LoginLogo` 的页面私有 CSS 中保留 `--border-width` 与 `--color-border` 的细描边。用户随后反馈阴影不好看，因此移除 `--shadow-low`，保持图标平面呈现，不以另一套投影替代。描边向内偏移一个边框宽度，不占布局空间或缩小 SVG 内容，底板保持纯白，原有圆角、尺寸及页面背景不变。边界通过主题令牌适配浅深色，不修改应用母版、导出资源或菜单栏图标。

问答输入区按 Astryx Chat 官网示例使用 `ChatLayout` 的底部停靠结构，由毛玻璃 dock 承载 `ChatComposer`，消息区和输入区共享同一滚动上下文。输入使用官方 `ChatComposerInput`，由组件负责内容增长和换行，页面在提交键上拦截默认清空行为以保留未接入服务时的草稿，仍尊重 IME 组合输入。输入框不额外显示知识库依据提示，避免在输入区重复表达回答来源；恢复 ChatComposer 的悬浮阴影、28px 聊天圆角和单行起始输入，不再以自定义实心底栏、扁平边框和三行固定文本区覆盖官网组件的基础层次。
输入区不显示 Enter / Shift + Enter 快捷键说明，提交与换行仍由输入事件处理，底部只保留必要的未接入状态提示。
未接入发送错误由页面私有组件渲染为紧凑的 warning 浮层，复用 Astryx 的 warning 颜色和图标语义，定位到输入框上方且不参与 dock 高度计算；右侧提供独立关闭按钮，关闭只隐藏提示、不清除草稿，避免状态提示出现或消失时推动消息区和输入区重新排版。

消息列表直接作为 `ChatLayout` 的内容使用 `ChatMessageList`，继承 spacious 密度并保持默认的 bottom anchor，使短会话贴近输入区、长会话自然滚动；不额外包一层独立滚动容器，也不把示例会话强制 top 对齐。用户问题继续使用填充气泡，助手回答使用 ghost 内容列承载正文和来源卡片，保留钩玄自己的引用交互。

页面入口只负责路由状态、业务状态和页面组合。问答页面将欢迎区、输入区、消息内容与来源详情拆为页面私有组件，知识库页面将筛选、表格与详情拆为页面私有组件；每个界面组件都在自己的目录维护 `index.tsx` 与 `index.css`。页面组件 barrel 只聚合本页面的组件导出，不引入路由组件，避免形成循环依赖。

移除显示“钩玄 / 界面预览”的全局顶部栏及其 52px 布局占位，保留原生窗口标题和系统按钮。Preload 只读暴露平台名称，macOS 通过根布局变量让侧栏顶部避让窗口按钮，并用不占布局高度的顶部透明区域支持窗口拖动；页面按钮和输入不进入拖动区域。其他平台保留原生标题栏，不额外增加避让空间。

问答右侧不显示新建会话或当前会话标题栏，移除其分隔线和 64px 占位，使欢迎内容与消息区使用完整高度。当前会话仍由左侧列表选中项和问答区域的可访问名称标识。

设置菜单与会话列表均使用 Astryx `SideNavSection` 和 `SideNavItem`，复用相同的项目间距、行高及内边距，不额外定义菜单间距。设置侧栏顶部仅保留返回问答链接，其下直接显示菜单，不展示设置标题或保留其空白占位；右侧页面仍显示自身标题。

知识库表格操作列由 66px 调整为 96px，为单元格内边距和 Astryx 小号按钮保留足够宽度，避免“查看”文字被截断；资料名称继续使用弹性列。

问答侧栏底部通过 Astryx `SideNav.footerIcons` 单行槽左右排列两个 Button：左侧文字登录，右侧仅显示齿轮设置图标，分别进入已有登录与设置路由。操作栏不叠加水平内边距，按钮水平内边距使用 8px，使左右内容与会话列表对齐；分隔线下留 8px，保留原有按钮高度和侧栏底部内边距。移除底部访客头像、未登录说明和独立设置行。齿轮使用 Radix 官方 `GearIcon`，在 Astryx Button 图标槽内使用 `1em` 尺寸并继承按钮颜色，设置按钮保留可访问名称、焦点样式和提示。

### Main 请求与登录代次

`request.ts` 以 openapi-fetch 接 Electron net.fetch，在 ready 后初始化；HTTP、SSE 和上传共用 AuthSession。访问令牌在内存，刷新令牌由 safeStorage 加密单独持久化，不进入 SQLite 或 Renderer。

`auth.ts` 保存账号、登录代次、令牌版本和期限；提前续期与并发 401 共用 single-flight，迟到旧 401 优先使用已有新版本。登录无需认证，刷新禁用递归刷新。认证成功最多重放一次且仅限可重建请求，提交或上传保留原幂等键；网络结果不明不盲重发。403、429 和暂时网络失败不清凭据；确定吊销才结束代次并合并通知。

退出或切换账号中止旧请求和订阅，写入前检查代次；IPC 返回错误码、提示、请求 ID 和可重试状态，不传自定义 Error 对象属性。SSE middleware 不读取流正文，连接与心跳超时由 stream 管理。

### 类型契约与进程边界

`shared/api.generated.ts` 由受版本控制的 OpenAPI 生成并被 Main 实际消费；IPC、事件和错误定义为浏览器兼容的纯类型与校验，不 import Electron、Node 或 Main 模块。

`ipc.ts` 检查 sender 和参数，Preload 只暴露专用业务方法及订阅清理函数，不暴露通用 ipcRenderer。实际消费者接入时移除 `@electron-toolkit/preload`，不引入通用请求代理到 Renderer。

### SSE、reducer 与 SQLite

eventsource-parser 负责分帧，每个 data JSON.parse 后校验公共事件。按 runId 和序号去重，通过类型化 IPC 供 useReducer 管理预览、核验、权威快照和终态。文本结束不等于回答完成；失败和取消预览不能作已确认正文。路由切换只调整界面订阅，不停止 Main 的流与缓存写入。

缓存使用 `node:sqlite`，验证 Electron 内建 Node 兼容性。批量事务保存消息投影、引用、运行及连续已应用序号，终态立即提交；仅已落库序号作为恢复位置。不逐 token 同步写库，测量 Main 阻塞。

先显示缓存后刷新，使用会话修订和消息 / 运行 ID 合并。启动、焦点与联网后分批核对缓存 ID，不将分页缺席当删除；失败保留待刷新缓存，明确不可访问才清理并留下本地删除标记拦截迟到结果。账号缓存隔离，退出清理历史缓存；草稿与界面偏好独立按账号保存。离线只读历史与本地偏好，不排队业务写入。初值 30 天、100 会话、目标 200MB，损坏缓存可重建。

### 路由、页面与管理员入口

TanStack Router 文件路由配 Hash History，路由实例在渲染树外。登录、chat 草稿 / 会话、settings 与管理员 knowledge 共享实际布局；路由 ID 为选中会话依据，beforeLoad 检查账号，loader 只经 Preload 读数据，写操作由用户触发。URL 不携带令牌和正文。

管理员上传经原生文件选择器和专用 Main 方法，Renderer 不接受任意本地路径读取权限。页面轮询任务，离开停止轮询但不停止服务端任务；审核对照解析与定位，评测通过后显式发布或回滚。

### 三态主题与安全样式

设置提供 light / dark / system，默认 system。偏好由 Main 现有本地设置保存，登录页、工作台和原生窗口统一通过 `nativeTheme.themeSource` 与 Renderer 根 Astryx Theme 使用同一 mode，复用已安装 token 和根同步行为，不加主题库。系统变化实时响应，固定模式不变；窗口显示前恢复偏好与背景，避免闪烁，不重建会话或中断运行。

保留 sandbox / contextIsolation / nodeIntegration 默认值；生产只加载本地打包页，限制导航、新窗口和允许的平台服务地址。Markdown 链接、图片及来源访问经白名单与授权，不自动拉任意远程资源。CSP 按实际 Astryx / StyleX 运行需求收紧，生产禁用宽泛 script 规则；样式需动态注入时验证 nonce 等受限方案，不承诺未经验证的一刀切禁用 inline。

## Risks / Trade-offs

- native SQLite 同步操作阻塞 Main → 合并批量写入并测量耗时，避免无数据依据引入额外进程。
- 续期、账号切换和迟到事件竞态 → 代次及令牌版本检查，故障场景验证。
- CSP 与实际样式注入不兼容 → 在打包页面验证组件与弹层，按来源收紧并记录必要规则。

### 本机界面验收环境

macOS 自动化中曾出现坐标操作报 `noWindowsAvailable`、可访问状态与截图不一致的问题。仅本次预览通过 `electron-vite preview --skipBuild -- --disable-gpu` 使用软件渲染后，画面更新与坐标拖动恢复；该诊断参数未写入项目配置，不能据此认定正式客户端需要关闭 GPU。

最新 SVG 接入时保留标准热更新启动方式。刷新窗口后曾出现空白，重启开发进程后工作台恢复；编译模块与 SVG 响应已核对。自动化再次出现 `noWindowsAvailable`，未能完成进入登录页后的最终视觉确认，不以先前独立路径版本的截图替代最新资源验收。

底板边界的初次调整已通过静态检查，开发服务器记录了 CSS 热更新，当时响应包含描边和阴影；自动化能读取登录页，但截图与输入操作未可靠反映最新状态，不能据此认定最终视觉验收通过。后续用户确认不接受阴影，最终方案只保留细描边。未为该问题修改运行配置或重启现有开发应用。

## Migration Plan

先交付界面和本地主题，再按 Main 请求和凭据、业务类型桥接、缓存及流式页面顺序接入，每项同步真实 OpenAPI 与公共事件。SQLite 以本地 schema 版本迁移，损坏时只重建历史缓存，不删除独立偏好。保持现有用户目录和安全窗口配置；失败回退保留可恢复历史与加密凭据格式说明。
