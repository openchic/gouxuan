## Purpose

依据指定且授权的语料版本回答保险咨询，向用户提供连续正文预览、经过严格核验的结论和独立可查的来源，同时在长会话中按预算保留可信用户事实，证据不足或条件不明时明确说明与追问。

## ADDED Requirements

### Requirement: 授权且固定版本的证据

问答 MUST 只在本次绑定的语料集合中使用符合产品、版本、有效状态和访问权限的证据，补充理解结论所需的完整条款上下文，并区分条款与咨询知识来源。

#### Scenario: 产品版本限制

- **WHEN** 问题指定产品与资料版本
- **THEN** 召回及引用符合指定范围，不混用其他产品或未授权资料

#### Scenario: 运行期间发布变化

- **WHEN** 运行提交后当前发布版本改变
- **THEN** 本次仍使用提交时绑定的版本与配置

### Requirement: 有界质量与追问

回答流程 MUST 遵守配置的总预算、最多两轮检索和一次修订；引用归属及版本必须程序核验，不能只依赖模型评分。证据不足、来源冲突或缺少必要用户事实时明确说明或追问。

#### Scenario: 无依据结论

- **WHEN** 没有支持确定结论的资料或来源冲突未解决
- **THEN** 不产生无依据确定结论，说明缺口、冲突或需要补充的信息

#### Scenario: 达到边界

- **WHEN** 检索或修订达到上限且仍不完整
- **THEN** 结束本次运行，只给有依据部分及缺口，不继续无限循环

### Requirement: 部分结构化正文预览

系统 MUST 从部分结构化输出中展示公开回答正文增量，标识为生成中；未完成原始 JSON 不可作为已确认最终回答，内部推理和核验修订草稿不得公开。

#### Scenario: 尚未闭合正文

- **WHEN** 模型陆续输出未闭合的 answer 字符串
- **THEN** 用户连续看到对应正文增量，预览保持未确认状态

#### Scenario: 最终结构不合法

- **WHEN** 模型结束后原始完整文本不满足严格格式
- **THEN** 运行不能以补齐的部分对象判定成功，报告失败或在预算内修订

### Requirement: 严格最终确认与自包含引用

回答 MUST 在完整格式、引用归属和证据支持核验通过后持久化最终正文与来源快照；快照包含文本、标题、定位、出处和资料版本，资料索引变化后仍可核对。

#### Scenario: 核验通过

- **WHEN** 候选正文及引用全部通过核验
- **THEN** 保存权威回答与来源，预览可被最终结果确认或替换

#### Scenario: 原索引不再使用

- **WHEN** 原文档不属于当前在线索引
- **THEN** 历史回答的授权来源快照仍可查看和核对

### Requirement: 按预算自动摘要

历史超出输入分配预算时系统 MUST 每次运行最多生成一次摘要，保留预算内近期生效原文，当前问题与必要证据优先；摘要不作为保险结论证据，失败或取消预览不参与摘要。

#### Scenario: 长会话

- **WHEN** 有效历史超出本轮输入预算
- **THEN** 触发至多一次摘要，摘要和近期原文仍受预算限制并记录本轮用量

#### Scenario: 摘要失败

- **WHEN** 摘要超时或格式不合法
- **THEN** 保留旧有效摘要并用预算内近期原文继续，缺必要事实时追问

### Requirement: 摘要事实回查及有效范围

摘要 MUST 关联覆盖消息与配置版本，用户事实可回查原用户消息，较新明确说明优先；覆盖范围失效时重建，写回不得跨越修订、租约或删除边界。

#### Scenario: 用户更正事实

- **WHEN** 用户更正摘要中的年龄或保障信息
- **THEN** 采用较新说明并能核对原消息，不把旧摘要当权威事实

#### Scenario: 重跑或删除

- **WHEN** 摘要范围包含本轮旧回答或会话已经删除
- **THEN** 不复用无效范围，不写回已删除会话
