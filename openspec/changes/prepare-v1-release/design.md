## Context

完整发布验收在六个功能 change 完成后实施；图标资源准备及开发 Dock 接入可独立先行。当前仅有本地检查和基础 API Compose，尚无分栈 CI、正式公证或生产闭环；产品图标接入不代替安装包验收。setup-monorepo 的 2.17、4.11、5.1、5.2 发布部分、5.5、5.8 CI 部分在这里验收。

## Goals / Non-Goals

**Goals:** 提供真实质量、可恢复部署与可安装分发证据，未完成上线条件可明确定位。

**Non-Goals:** 不搭评测管理平台，不设计多实例、高可用、自动更新或账务系统；不因发布引入可选 hoist / 包管理器维护。

## Decisions

### 分栈 CI

client、site、api 使用独立 workflow 和原生 paths 过滤，覆盖共享配置、锁文件、生成契约与根脚本的实际依赖；固定安装采用 pnpm frozen-lockfile 和 uv locked。API workflow 执行现有 check:api、Postgres / pgvector 集成及迁移验证和镜像构建，client 检查 OpenAPI TS 生成无差异。不用影响图框架，也不把私有 golden 或模型密钥放进公开 CI。

### 单部署与启动顺序

API、问答 worker、资料 worker 使用同一镜像及配置，各自独立进程和并发。生产显式选独立 Compose 配置，禁止意外加载开发挂载或 reload；开发 dev:api 编排数据库、本地私有存储、一次迁移、API 与两 worker，管理员初始化单独 CLI。

顺序为基础存储就绪、单次迁移、管理员 CLI、API 与 worker；每进程检查迁移而不自行改表。HTTPS 入口关闭 SSE 缓冲并配置心跳与超时，服务分别报告数据库、存储、两 worker 和 QA 就绪。问答并发初值 4，资料 1，供应商并发单独限制。

### 真实问答与质量门禁

首批授权资料确认格式、产品版本、来源、使用展示权限及审核人；配置实际 embedding / 维度、生成与 rerank 及供应商区域、预算和保留设置。固定私有 golden 在 data/eval 本地忽略副本和私有存储管理，`eval/run.py` 复用 app 业务，输出报告并人工复核。

质量覆盖正常问答、无证据、冲突、缺用户事实、追问、范围外、长会话摘要、事实更正和摘要失败降级；严重错误结论或引用不能发布。测量全链路实际 token、失败、取消和未知调用用量；目标负载结果用于调初值，不宣称未经验证的 SLA。

### 保留与恢复

通过已有清理入口落实公共事件终态后 24 小时、最小用量 30 天及未关联对象清理。活动运行和可回滚 manifest 保护文档及索引。数据库和原始资料每日备份，保留 7 天；在独立恢复环境重放删除清单并验证已删内容不重新可访问，整库发布可回滚。备份成功日志不能替代恢复验证。

### 桌面与官网发布

图标资源先行存于 `apps/electron/build/icons/gouxuan-v1`，不覆盖现有模板图标。使用登录页已选定的尖端回钩路径，`source/app-icon.svg` 为 1024 × 1024 全幅白底母版，图形为 `#1b1b1b`。ImageGen 生成参考稿并记录提示词；实际交付由可编辑 SVG 导出，避免 AI 颜色漂移、尺寸偏差和嵌入位图伪装矢量。透明前景层保持同画布、未遮罩、不携带阴影，可供后续 Icon Composer 分层导入。

原版外轮廓近似几何居中，但右侧粗弧使视觉重量偏右。用户确认后只对应用图标做水平光学校正：母版主体左移 30px，将 `translate(153 124)` 改为 `translate(123 124)`，保持原路径、纵向位置、`scale(1.5)`、颜色和背景不变。透明前景与兼容 ICNS / iconset 同步从母版导出；兼容版按底板比例换算移动。菜单栏采用独立定位，不做本次校正；重新导出后核对其 SVG、1x PNG 与 2x PNG 的哈希，确认内容未变。位置校正不修改登录页组件或打包配置。

现有 Electron 打包链提供独立兼容 ICNS，圆角白色底板带透明外边距，并输出 16 / 32 / 128 / 256 / 512pt 的 1x、2x 共十个 iconset 表示。未裁圆角母版和已裁切兼容资源分开，后者不得作为现代分层图标输入。菜单栏使用透明纯黑 Template 图像，16px / 72dpi 与 32px / 144dpi 配对，保留 `Template` 和 `@2x` 命名；仅轻微增粗小尺寸轮廓，系统负责浅深色着色，不使用应用图标的白底。导出脚本验证尺寸、密度、透明度、图形纯色和 ICNS 表示，并保留可视预览与验证记录。资源准备阶段不修改打包配置或新增 Tray；应用图标接入按下面的独立步骤执行，`.icon` 工程、实际菜单栏和分发安装验证仍属于后续验收。

用户截图确认运行中的 Dock 仍显示 Electron 默认图标。原因是此前只导出了产品资源，开发 Main 未调用 Dock 图标接口，打包也未指定新 ICNS，仍回退到模板资源。macOS 开发启动在 `app.whenReady()` 后调用 `app.dock.setIcon`，使用 `app-icon-macos-1024.png` 的圆角白底与透明外边距兼容图，不使用全幅未遮罩母版；资源路径相对开发 Main 输出解析，调用限定开发模式与 macOS。正式应用由 `electron-builder.yml` 的 `mac.icon` 明确引用 `build/icons/gouxuan-v1/Gouxuan.icns`，不在打包运行中依赖源码资源路径。接入不覆盖原模板文件、不修改 Electron 依赖包的 Info.plist、不重启系统 Dock、不增加 Tray，不改变 appId、名称及用户目录。Main 启动逻辑变更后重启现有开发进程，并继续保持热更新运行；签名、公证、安装图标和显示名仍由 3.1 / 3.2 完整验收。

本地接入检查已通过，编译后 Main 中的图标路径、1024px PNG 尺寸和 ICNS 标识已核对；开发应用已按标准 dev 命令重启并保持运行，启动无错误。macOS Dock 自动化读取超时，尚未获得更新后 Dock 的实际截图，3.7 保留视觉确认待完成，不以启动日志替代系统显示验收。

取得产品图标及正式分发签名、公证所需凭据后，用独立 macOS release workflow 构建签名 DMG / ZIP、完成公证并验证安装启动。核对 appId、中文显示名、窗口、图标、用户目录与 ASCII 产物名。既有开发签名启动不代替正式分发验收。

HTTP 保持 /v1/，固定支持客户端版本并验证 OpenAPI、IPC 和公共事件实际消费兼容；不自动提交问答或切换语料来修复版本不兼容。官网静态部署后配置 HTTPS 下载地址，核对下载到的签名版本，更新 README 的运行及分发说明。

## Risks / Trade-offs

- 私有语料、模型或凭据未提供 → 保留对应未完成验收，不替换成 mock 结果。
- 生产误载开发 override → 显式配置文件与合并结果检查。
- 恢复重新暴露已删除记录 → 独立删除清单、恢复后重放再开放服务。
- 协议变更破坏旧客户端 → 发布前按支持版本验证，不无条件声称兼容所有旧版本。

## Migration Plan

先执行 CI 与合成完整启动，再在受控环境配置真实资料、模型、评测和恢复，最后完成正式分发与官网上线。服务回退使用兼容镜像与数据库迁移策略，语料回退切完整 manifest；桌面和官网回退至已验证产物。任何尚未提供的上线输入记录为对应 tasks 未完成，不能把整个 change 标为可发布。
