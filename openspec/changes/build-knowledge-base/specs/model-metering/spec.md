## Purpose

为摄取、评测、摘要和用户问答提供真实模型调用的可追溯计量，按调用标识关联操作者与任务或运行，明确失败、取消和供应商未知结果的用量状态，同时限制敏感正文与密钥的保存。

## ADDED Requirements

### Requirement: 实际调用关联与幂等计量

系统 MUST 按真实调用 ID 记录供应商、模型、配置、供应商请求 ID、计量单位、耗时和状态，并关联账号及资料任务或问答运行；同一调用不重复统计，新实际重试调用单独记录。

#### Scenario: 重复记录

- **WHEN** 同一次调用的结果因恢复重复提交
- **THEN** 只有一份生效计量记录

#### Scenario: 真实重试

- **WHEN** 安全重试产生新的供应商调用
- **THEN** 分别记录两个调用的实际用量与状态

### Requirement: 失败取消及未知用量

系统 MUST 保留成功、失败和取消中已产生的用量，不能把未知用量记为零；终态后的用量补录不能恢复内容或改变业务终态。

#### Scenario: 生成取消

- **WHEN** 模型已产生 token 后运行取消
- **THEN** 已知用量保留并关联取消运行

#### Scenario: 供应商结果未知

- **WHEN** 连接失败而无法确认实际消费
- **THEN** 保留已知单位并标为待核对，后续可补录确认值

### Requirement: 最小数据与保留

计量记录 MUST 不保存问题、回答、检索原文或密钥，并按配置期限保留最小计量字段，与会话内容清理独立。

#### Scenario: 内容删除

- **WHEN** 关联会话被用户删除
- **THEN** 剩余用量不包含可恢复的会话内容

#### Scenario: 保留期结束

- **WHEN** 用量达到配置保留期限
- **THEN** 按策略清理，不影响仍有效的会话内容
